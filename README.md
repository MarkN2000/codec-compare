# ききくらべ

ローカルの音源をブラウザ内で変換し、音質とサイズを比較します。仕様は[spec.md](spec.md)。外部フォント・解析サービス・音声アップロードは使いません。

## 起動

Node.js 22以上を使用します。

```sh
npm ci
npm run dev
```

`http://127.0.0.1:4173` を開きます。`npm run build` で生成する `dist/` を静的ホスティングに配置できます。URLは相対指定なのでGitHub Pagesのサブディレクトリにも対応します。

## 修正版音声コア

公式 `@ffmpeg/core@0.12.10` にはOpus 48 kHzのスタック不足があるため、上流の[修正 #824](https://github.com/ffmpegwasm/ffmpeg.wasm/pull/824)を含む音声用コアを使用します。音質設定による回避はしません。

一時コアのOpus復号にはlibopusを使用します。FFmpeg 5.1.4のnative復号器では、低ビットレートのSILK音声の先頭でサンプルが欠落するケースを確認したためです。公式版への移行時もSILKのサンプル数と区間位置を検証します。

公式配布版への移行は、Opusの修正に加えて、このサイトで使う全形式の圧縮・復号・区間再生を検証してから行います。LC3はGoogle liblc3とFFmpeg公式の接続コードを現在のコアに組み込んでいます。[移植の内容](scripts/lc3/README.md)も公式版への移行時に見直します。

コアのビルドは初回とコア更新時だけ必要です。生成済みの成果物を保存して使い回すため、サイトの変更・公開のたびにコアを作り直す必要はありません。次の2通りから選べます。

**GitHub上で手動実行する場合：**

1. GitHub Actionsの「音声コアのビルド」を手動実行する。
2. 成功した実行の `audio-core` artifactを `vendor/core/` に展開する。
3. `npm test` と `npm run build` を実行する。

**ローカルで実行する場合：** Dockerがある環境では、次のコマンドでも同じコアを生成できます。

```sh
docker buildx build -f scripts/core.Dockerfile --output type=local,dest=vendor/core .
```

ビルド元コミット・依存音声ライブラリ・スタック容量はDockerfileで管理します。検証済みのコアを `vendor/core/` に同梱しているので、通常の起動・サイト更新ではコアの再ビルドは不要です。[ビルド記録](vendor/core/BUILD.md)を参照してください。

## 現在の実装

- UIはHTML/CSS/JavaScript。追加のUIフレームワークやバンドラーはありません。
- 基準PCMは元のレート・24 bit・最大2チャンネル。量子化はディザなしの丸めとクリップです。
- 入力をストリーム復号してサンプル数を数え、ヘッダー・エンコーダーのパディングを含まない基準サイズを算出します。PCM全体は保持しません。
- 変換用と再生用の2つのシングルスレッドWorkerを使います。変換は順番に実行し、各変換終了後にWorkerを解放します。
- 出力はBlob、入力参照はWORKERFS。再生用のFloat32 PCMは原則として現在・次区間と切替準備中の区間だけです。
- 再生区間は初回8秒、復号時間に応じて4～16秒。切り替えは5 msのフェードアウト後、同じ位置から5 msでフェードインします。
- 準備済みの基準PCMは再生・グラフで共有し、別パターンへ移っても現在に近い最大2区間を追加保持します。先行生成で現在区間を追い出さず、長い準備済み区間を短い結果で置き換えません。音源変更・シーク・再生し直しで破棄します。切替要求では100 ms巻き戻さず、4秒境界と直近の復号時間に応じて余裕を含め、期限切れによる再試行を減らします。
- 元の構成を維持する8／16／24 bit整数PCMと24 bit以下のFLACでは、不要な再量子化を省きます。倍精度化とリサンプルは維持し、浮動小数点・32 bit整数・非可逆圧縮・多チャンネルや特殊なチャンネル配置などでは従来の量子化を続けます。
- ループボタンで末尾から先頭に戻って再生します。先頭の区間復号を待つ場合があります。
- 上部は入力ファイルの容量、基準行は24 bitのPCM換算容量です。Opusは6～24 kbpsの低ビットレートも選択できます。
- LC3、SBC、G.722、G.711も比較できます。G.722は16 kHz・モノラル・64 kbps、G.711は8 kHz・モノラル・64 kbps固定です。G.711の設定内でμ-law／A-lawを選びます。LC3は7.5／10 msフレームを選択でき、目標ビットレートは音声全体の値です。
- SBCは生の`.sbc`、LC3は基準ビットストリームの`.lc3`、G.722／G.711はWAVとして保存します。Bluetoothの通信ヘッダーや機器固有の処理は含みません。mSBC・aptX系は追加していません。
- LC3・SBC・G.722・ADPCMは一度だけ連続復号し、遅延補正済みの32 bit float WAVをOPFSへ直接書き込みます。以後は再生・グラフでこの一時PCMを共有し、後半でも先頭から復号し直しません。リサンプル後の末尾も元の処理と一致するよう、符号化時のパディングを残します。保存用の圧縮ファイルは変えません。
- 対象形式の入力は解析時、比較パターンは変換完了前に一時PCMを準備します。初回の準備時間とストレージ使用量が増えますが、全量PCMをメモリに蓄積しません。一時PCMは1本512 MiB・合計1 GiBを上限とし、音源変更・パターン削除時に削除します。ページ終了時にも削除を試み、残ったファイルはWeb Locks対応環境で24時間経過後に整理します。保存不可・空き不足の場合は従来の復号に戻るため、後半の速度改善は保証しません。
- AACのPNS（ノイズ合成）は途中シークで乱数状態が変わり、ノイズ成分の個々のサンプルは全体復号と一致しない場合があります。
- 暫定上限：入力512 MiB、出力1本512 MiB、入力と出力の合計1 GiB。PCM・Worker・変換中のコピーのメモリは別途必要です。端末のメモリ保証値ではありません。
- 入力レートは8～192 kHz、最初の音声トラックを使用します。コアの対象入力はWAV、AIFF、FLAC、MP3、AAC、M4A、Ogg、SBC、LC3、対応音声を含むWebMです。
- 各設定の範囲と初期値は `model.js` に集約しています。ステレオの初期値はOpus VBR 128／MP3 CBR 192／AAC平均256 kbpsで、モノラルは各々半分。Vorbis品質4、FLACレベル5・24 bit、WAV 24 bitは維持します。レートは可能な限り元音源を維持します。
- SBCはBluetoothの代表的な設定と比較用の値に候補を絞り、44.1／48 kHzの初期値はステレオ328／345 kbps、モノラル193／198 kbps。Joint Stereo（モノラルはMono）・8サブバンド・16ブロック・Loudnessで符号化し、フレームのビットプールも検証します。
- LC3は10 msを初期値とし、1チャンネルあたり8／16／24／32／48 kHzで24／32／48／64／96 kbps。Bluetoothの124／124.8 kbpsの設定例も選べます。候補上限はモノラル128／ステレオ256 kbpsです。
- グラフは1024 FFT・2048サンプル間隔で計算し、約0.1秒へ集計します。48 kHzでは約21 msの窓を約43 ms間隔で分析するため、窓の間の短い変化は見落とす場合があります。全周波数ビンを残し、2つのグラフとパターン間で基準分析を共有します。FFT Workerは約8 msの処理時間ごとに待機して休止要求を受け付け、固定4窓ごとの待機を省きます。途中経過を残して再開し、周波数線は毎秒4回以下、差分画像・目盛りは再利用します。
- 完成した分析結果はページ内のBlob実体で識別してIndexedDBへ保存します。メモリ8 MiB・保存128 MiB・24時間を上限とし、保存できない環境でもメモリで継続します。ページ再読込をまたぐ音源の同一判定はしません。
- 結果はメモリへ即時に渡し、表示でディスク保存を待ちません。最大16件・2 MiBの保存待ちを最大4件ずつ保存し、超過時は古い低優先度の保存を省略します。未保存キーの照会を省き、容量は増分管理、管理情報の全件確認は初回・30秒間隔に抑えます。現在位置から16秒分の基準・選択音源の分析結果をメモリに優先して残します。
- 一時停止中は16秒分のまとめ復号から先行分析を進めます。再生中の追加復号は先読み4秒から再開し、先読み6〜7秒以上で8秒分をまとめます。実測時間はバッチ選択だけに使い、通常の先読み上限を超える待機条件を作りません。待機中の復号Workerと完了済みPCMを再利用し、追加PCMは最大2区間。前述の対象形式だけ一時PCMをストレージへ保存します。圧縮開始・グラフを閉じる際などにはグラフ用Workerを解放します。
- 再生中も余裕があるときはグラフを最大12秒先まで先行分析します。再生の先読み6秒以上・直近の4秒分析が2秒以内を条件とし、余裕が減れば次の4秒までに戻します。再生側が空いている間だけ未予約の将来区間を追加復号し、そのPCMを後の再生にも渡して二重復号を避けます。

## 検証

```sh
npm test
```

外部テストフレームワークを使わず、生成した信号を実際のWASMで全対応形式に変換します。24 bitの量子化、FLAC/WAVと基準PCMの一致、複数位置の区間復号、サイズ計算、再生タイムラインを確認します。追加形式では同じレート・チャンネルのPCM対照との位置合わせと末尾までのサンプル数、LC3・SBCでは各設定候補も検証します。

2026-10-30にGitHub Actionsとローカルで全テストを通過しました。Chromium系ブラウザでも7形式の変換、Opusの連続再生、AACへの切り替え、ADPCMの途中再生を確認しました。Android実機・Safari・Firefox・長時間音源での推奨スペックは未検証です。

2026-10-31の追加対応では全21テストを通過し、12形式の実WASM変換と区間位置、LC3・SBCの全候補を検証しました。ブラウザでは追加5形式の変換、LC3の試聴・保存、G.722／SBC／G.711への再生中の切り替えとグラフの追従を確認しています。

初期値の見直しとG.711設定の統合では全22テストを通過しました。SBCは全候補のフレームヘッダーでJoint Stereo／Mono・8サブバンド・16ブロック・Loudnessと代表値のビットプールを照合しています。G.711は両方式のWASM変換・区間復号・音源変更時の設定維持を検証し、ブラウザでも設定選択・変換・試聴を確認しました。

グラフ軽量化では全25テストを通過しました。実ブラウザのIndexedDBへ保存・読戻しした全パワーの一致とFFT Workerの休止・再開を検証しました。3分のOpus VBR 192 kbpsをCPU 6倍遅延の設定で90秒から158秒まで再生し、グラフの追従を確認しています。SBCでも中盤から末尾まで更新を確認しました。この条件は低性能端末の実機検証を代替するものではありません。先頭から復号する形式の初回準備時間は、音源の長さと端末性能に依存します。

1024 FFTへの変更と先読み条件の修正では全26テストを通過しました。遅い復号の実測値でも先読み4秒で再開できること、先読み8秒以内でのまとめ復号、Workerの再利用・解放を検証しています。ローカルのブラウザでは3分のOpus VBR 192 kbpsをCPU 6倍遅延で90秒から149秒まで再生し、グラフの更新を確認しました。同じPCで4秒・48 kHz・ステレオのFFT単体を7回計測した中央値は、2048で13.5 ms、1024で6.2 msです。復号や描画を含む全体の速度・低性能端末での動作保証を示す値ではありません。

一時PCMの保存では全27テストを通過しました。SBC・LC3・G.722・ADPCMの先頭・中盤・末尾を44.1／48 kHzで従来の復号結果と照合し、入力SBCの共通PCM条件、MEMFSに全量を蓄積しないこと、共有・削除・保存上限・保存失敗も検証しています。実ブラウザのOPFSで3分音源から4秒を取り出した3回の中央値は、先頭／150秒地点でSBCが39.9／46.2 ms、LC3が37.4／44.8 ms、G.722が12.4／14.3 ms、ADPCMが39.4／47.1 msでした。同じブラウザでの従来処理の150秒地点は各々700.2／419.1／144.7／260.8 msでした。計測はこのPCの条件で、初回の変換・PCM準備時間は含みません。

全形式に共通する分析・保存の改善では全29テストを通過しました。保存が遅くても結果を使えること、待ち行列の上限、容量の増分管理、近い区間の保持、16秒分の先行分析とPCM再利用、FFTの休止再開と数値一致を検証しています。実ブラウザで4秒・48 kHz・ステレオのFFT Workerを7回測った往復時間の中央値は88.4→7.5 msでした。32区間の実IndexedDB保存は223.5→54.0 ms、呼出側の保存待ちは217.5→0.2 ms、管理情報の走査は33→1回で、読戻し値は一致しました。これはWorkerと保存の個別計測で、復号・描画を含む全体の倍率ではありません。3分音源をCPU 6倍遅延のブラウザでMP3 192 kbpsの90〜161秒、続いてOpus VBR 192 kbpsで末尾まで再生し、グラフの追従とエラーがないことを確認しています。低性能端末の実機検証は未実施です。

基準音への切り替え改善では全32テストを通過しました。4秒境界の前後での切り替え、基準へ戻る際のPCM再利用、グラフ先読み時の保持上限と長い区間の保護、切り替え時刻の一致を検証しています。16／24 bitのWAV・FLACをモノラル／ステレオ、44.1／48 kHzで従来処理と比較し、量子化省略後も全サンプルの一致を確認しました。このPCの実ブラウザで103.7秒付近からOpus→基準へ切り替えた測定は、WAV入力で初回52.4 ms・戻る際20.1 ms、MP3入力で初回115.8 ms・戻る際20.1 msでした。初回の切替用復号は各1回、戻る際は0回でした。グラフなしの単独計測であり、全端末の待ち時間を保証する値ではありません。
