# Codec Compare

ローカルの音源をブラウザ内で変換し、音質とサイズを比較します。仕様は[spec.md](spec.md)。外部フォント・解析サービス・音声アップロードは使いません。

## 起動

Node.js 22以上を使用します。

```sh
npm ci
npm run dev
```

`http://127.0.0.1:4173` を開きます。`npm run build` で生成する `dist/` を静的ホスティングに配置できます。URLは相対指定なのでGitHub Pagesのサブディレクトリにも対応します。

## 修正版音声コア

公式 `@ffmpeg/core@0.12.10` にはOpus 48 kHzのスタック不足があるため、上流の[修正 #824](https://github.com/ffmpegwasm/ffmpeg.wasm/pull/824)を含む音声用コアを使用します。音質設定による回避はしません。

1. GitHub Actionsの「音声コアのビルド」を手動実行する。
2. 成功した実行の `audio-core` artifactを `vendor/core/` に展開する。
3. `npm test` と `npm run build` を実行する。

Dockerがある環境では、次のコマンドでも同じコアを生成できます。

```sh
docker buildx build -f scripts/core.Dockerfile --output type=local,dest=vendor/core .
```

ビルド元コミット・依存音声ライブラリ・スタック容量はDockerfileで管理します。**修正版コアのビルド・取り込みは現在未完了です。配布版コアを使う状態ではOpusのテストが失敗します。**

## 現在の実装

- UIはHTML/CSS/JavaScript。追加のUIフレームワークやバンドラーはありません。
- 基準PCMは元のレート・24 bit・最大2チャンネル。量子化はディザなしの丸めとクリップです。
- 入力をストリーム復号してサンプル数を数え、ヘッダー・エンコーダーのパディングを含まない基準サイズを算出します。PCM全体は保持しません。
- 変換用と再生用の2つのシングルスレッドWorkerを使います。変換は順番に実行し、各変換終了後にWorkerを解放します。
- 出力はBlob、入力参照はWORKERFS。再生用のFloat32 PCMは原則として現在・次区間と切替準備中の区間だけです。
- 再生区間は初回8秒、復号時間に応じて4～16秒。切り替えは5 msのフェードアウト後、同じ位置から5 msでフェードインします。
- ADPCMはシークずれを避けるため先頭から読み捨てます。長い音源では再生準備が遅くなる制約があります。
- AACのPNS（ノイズ合成）は途中シークで乱数状態が変わり、ノイズ成分の個々のサンプルは全体復号と一致しない場合があります。
- 暫定上限：入力256 MiB、出力1本128 MiB、入力と出力の合計512 MiB。PCMやWorkerのメモリは別途必要です。端末のメモリ保証値ではありません。
- 入力レートは8～192 kHz、最初の音声トラックを使用します。コアの対象入力はWAV、AIFF、FLAC、MP3、AAC、M4A、Ogg、対応音声を含むWebMです。
- 各設定の範囲と初期値は `model.js` に集約しています。初期値はOpus/MP3/AAC 128 kbps、Vorbis品質4、FLACレベル5・24 bit、WAV 24 bit。レートは可能な限り元音源を維持します。

## 検証

```sh
npm test
```

外部テストフレームワークを使わず、生成した信号を実際のWASMで7形式に変換します。24 bitの量子化、FLAC/WAVと基準PCMの一致、複数位置の区間復号、サイズ計算、再生タイムラインを確認します。

ブラウザでの確認はローカルのChromium系ブラウザで実施します。Android実機・Safari・Firefox・長時間音源での推奨スペックは未検証です。

## 公開

GitHub Pages用ワークフローは手動実行です。修正版コアを取り込み、リポジトリのSettings → PagesでGitHub Actionsを選んで実行します。独自ドメインは同じ設定画面で指定します。ドメイン名はまだ未指定です。

音声コアのライセンス文書はビルド成果物の `licenses/` に含め、サイトにも同梱します。ライブラリのソースとビルド手順は `scripts/core.Dockerfile` を参照してください。
